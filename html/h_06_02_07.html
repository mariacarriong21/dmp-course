>>Un equipo escribe «datos anonimizados» sobre un conjunto cuya clave de seudonimización está en el mismo equipo donde se hace el análisis. ¿Qué consecuencia tiene ese error?<<
( ) Ninguna relevante: es una cuestión terminológica
(x) Cambia la base legal, lo que se puede depositar y lo que se declara al comité
( ) Solo afecta al apartado de compartición
( ) Obliga a repetir la recogida de datos
[explanation]
No es terminología. Un conjunto seudonimizado **sigue siendo dato personal**, con todo lo que eso arrastra: base legal, medidas de seguridad, límites al depósito y declaración ante el comité.

Es uno de los errores más repetidos y de los más caros, porque se descubre tarde.
[explanation]

>>¿Por qué un plan de gestión de datos incluye un apartado sobre muestras biológicas, si las muestras no son datos?<<
( ) Porque el RGPD las considera datos personales
(x) Porque están vinculadas a los sujetos y a los datos, y ese vínculo no se documenta en ningún otro sitio
( ) Porque las convocatorias lo exigen desde 2022
( ) Porque sustituye a la documentación del biobanco
[explanation]
Cada muestra lleva un código que la vincula a un sujeto —el mismo problema que la clave de seudonimización— y genera datos que son un conjunto del inventario.

El protocolo describe el procedimiento clínico y el consentimiento da la autorización; **el vínculo entre muestra y dato no aparece en ninguno de los dos**.
[explanation]

>>Un proyecto tiene el consentimiento firmado para el análisis de las muestras en el estudio. ¿Puede conservarlas para investigación futura?<<
( ) Sí, mientras estén seudonimizadas
(x) Solo si el consentimiento lo contempla expresamente
( ) Sí, si lo autoriza el investigador principal
( ) Sí, siempre que se depositen en un biobanco
[explanation]
El consentimiento de las muestras y el de los datos son **autorizaciones distintas y con alcances distintos**. Es frecuente que cubra el análisis para este estudio pero no la conservación posterior.

Suponer lo contrario es el error más caro de este apartado, porque se descubre cuando ya no hay forma de volver a preguntar.
[explanation]

>>¿Qué tiene de particular el código de análisis frente a los datos, en un proyecto biomédico?<<
( ) Que no necesita licencia
( ) Que no puede depositarse en repositorios públicos
(x) Que se puede publicar en abierto sin restricción legal, porque no contiene datos personales
( ) Que su publicación exige autorización del comité de ética
[explanation]
El código, los protocolos y los flujos de trabajo **no contienen datos personales**: no dependen de un consentimiento ni de una autorización para salir. Publicarlos es una decisión enteramente del equipo.

Por eso son la vía más accesible para que un proyecto con datos restringidos tenga presencia real en ciencia abierta.
[explanation]

>>Al inventariar sus datos, un equipo anota lo que recoge, lo que extrae de la historia clínica y las imágenes. ¿Qué es lo que con más frecuencia se olvida?<<
( ) Las variables demográficas
(x) Los conjuntos derivados: la base limpia de análisis y las tablas de resultados
( ) Los datos del centro coordinador
( ) Los metadatos del proyecto
[explanation]
Los **derivados**. La base limpia que realmente se analiza casi nunca coincide con lo que se recogió, y las tablas de resultados son un conjunto con vida propia.

Tienen además una particularidad: suelen ser los únicos conjuntos que el proyecto puede compartir en abierto.
